# 桌面组件化：计划

把现在固定的「额度卡片」「用量卡片」换成**可以自己搭的桌面组件窗口**：窗口是一张网格，往里放组件，每个组件有自己的属性。现在的各种样式变成内置模板。

状态：计划定稿前的草案（2026-11-02），在 `dev` 分支上做。

## 1. 目标和不做的事

要做到：

- 能建多个桌面窗口，每个窗口自己定行列数、背景、文字颜色、透明度、是否置顶。
- 窗口里放组件：圆环、大数字、进度条、走势图……每个组件绑定一项数据（哪家、哪个额度、哪个统计范围），属性可改。
- 在设置页里编辑，右边实时预览；桌面上的窗口只负责显示（拖动位置、拖右下角缩放照旧）。
- macOS 和 Windows/Linux 用**同一份配置格式**，同一份布局在两边画出来一样，还能导出、导入。
- 老用户升级后看到的卡片和现在一样（自动迁移成模板）。

不做：

- 自由画布（任意坐标、任意大小、可以重叠）。只做网格。
- 公式、脚本、自定义数据源（KWGT、Rainmeter 那一套）。数据只来自 UsageBar 已有的额度和统计。
- 在桌面上直接编辑。以后有需要再加。

## 2. 调研结论

| 参考 | 怎么做的 | 我们拿来什么 |
|---|---|---|
| Rainmeter（Windows 桌面组件） | 一个皮肤由「measure」（取数据）和「meter」（显示）组成，meter 通过 MeasureName 绑定 measure；位置用像素，从皮肤左上角算，后写的盖在前面；可以继承一组公共样式（MeterStyle）；「布局」功能能保存、载入一整套皮肤和位置 | **数据和显示分开**：组件 = 显示方式 + 绑定的数据；**窗口级公共样式、组件可覆盖**；布局的保存和载入对应我们的模板和导入导出 |
| KWGT（Android 组件编辑器） | 组件树，像图片编辑器的图层；横排、竖排、重叠三种分组，可以嵌套；有全局变量 | 证明了编辑器的复杂度主要在嵌套分组。我们用网格代替嵌套分组，省掉这一层 |
| macOS / iOS 小组件（WidgetKit） | 固定几种尺寸（小、中、大），按尺寸切换排版；可配置的小组件用 AppIntent 让用户选选项 | **尺寸用预设**：新建窗口先选预设尺寸，和我们 1.11 统一的三种排列尺寸对应 |
| Grafana | 看板按 24 列网格排，每个面板用 `gridPos {x, y, w, h}` 定位置，整个看板存成一份 JSON | **网格坐标存成 JSON**，配置格式直接照搬这个思路 |
| gridstack.js（网页网格拖拽库，MIT，无依赖，v14） | 拖动、改大小、碰撞检测、可选的往上补空（float）、布局存成 JSON | 规则可以参考，但**不用这个库**：Mac 那边没有对应的库，两边各写一套简单规则更容易保持一致；它解压后约 2 MB，我们只用得到一小部分 |
| WebView2（Windows 的网页内核） | 每个 WebView 实例会有自己的一组进程，实例越多占用越大；同一环境下可以共用浏览器进程 | Windows/Linux 上每个桌面窗口是一个 WebView，**窗口数量要设上限**（先定 6 个） |

## 3. 概念

- **窗口**：桌面上的一块。属性：名字、列数、行数、大小（缩放）、背景、文字颜色、透明度、背景透明度、置顶、显示「已用 / 剩余」、重置时间显示方式、按余量着色。后面几项是**公共样式**，组件可以单独覆盖。
- **网格**：每格 40pt，格间距 8pt，窗口四周留 16pt。窗口宽 = 16×2 + 40×列 + 8×(列−1)，高同理。
- **组件**：类型、占哪几格（x, y, w, h）、属性。组件在自己的格子区域里等比缩放填满（沿用 1.11 的放大填满逻辑，最多 1.6 倍），所以留白只在组件内部处理。
- **模板**：一份预先排好的窗口配置。现在的 10 种样式 × 排列组合各对应一个模板。

预设尺寸（和 1.11 的三种尺寸对上）：

| 预设 | 列×行 | 大小（100%） | 对应现在的 |
|---|---|---|---|
| 横排 | 9×4 | 456×216 | 左右排 480×200 |
| 竖排 | 5×6 | 264×312 | 上下排 296×340 |
| 横条 | 6×2 | 312×120 | 紧凑、细条、占比条 340×150 |
| 方块 | 4×4 | 216×216 | 新增，放一两个圆环或数字 |

也可以自己填列数和行数。

## 4. 配置格式（两个平台共用）

```json
{
  "version": 1,
  "widgets": [
    {
      "id": "w1",
      "name": "额度",
      "cols": 9, "rows": 4,
      "scale": 1,
      "style": {
        "background": "dark", "text": "white", "opacity": 1, "bgOpacity": 1,
        "display": "used", "reset": "relative", "levelColors": true
      },
      "onTop": false,
      "items": [
        { "id": "a", "type": "header",  "x": 0, "y": 0, "w": 4, "h": 1, "props": { "source": "claude" } },
        { "id": "b", "type": "ring",    "x": 0, "y": 1, "w": 2, "h": 3, "props": { "source": "claude", "limit": "session" } },
        { "id": "c", "type": "ring",    "x": 2, "y": 1, "w": 2, "h": 3, "props": { "source": "claude", "limit": "weekly" } }
      ]
    }
  ]
}
```

- Mac 存在偏好设置的一个键里（JSON 字符串），Windows/Linux 存在 settings.json 的 `widgets` 字段。
- `props` 里只放和默认值不同的项；`style` 里没写的用窗口默认值，组件 `props.style` 可以覆盖。
- 窗口位置不进这份配置，沿用现在按显示器记的摆放逻辑，键名改成按窗口 id 记。
- `limit` 用稳定的名字：`session`（5 小时）、`weekly`（每周）。Windows/Linux 已经有 `kind` 字段；**Mac 现在只有显示用的文字和一个 weekly 标记，要先补上同样的 kind**。

## 5. 组件清单

默认大小和最小大小都按格子算（宽×高）。

**额度类**（属性：哪家 `source`、哪个额度 `limit`）

| 组件 | 来自现在的 | 默认 | 最小 | 额外属性 |
|---|---|---|---|---|
| 圆环 | 圆环样式 | 2×3 | 2×2 | 圈里显示名字、下面显示重置时间 |
| 大数字 | 大数字样式 | 2×2 | 2×2 | 细进度条开关 |
| 进度条行 | 标准样式的一行 | 4×1 | 3×1 | 下面一行显示重置时间 |
| 细条 | 细条样式的一行 | 4×1 | 3×1 | — |
| 重置倒计时 | 各样式里的「↻ 3h 25m」 | 2×1 | 2×1 | 相对 / 几点 |
| 预计用完 | 菜单里的「预计 … 用完」（**新组件，数据现成**） | 3×1 | 2×1 | — |
| 可用重置次数 | Codex 的「可用重置 2 次」 | 2×1 | 2×1 | 显示每次的到期时间（要 4×2） |
| 一家全部额度 | 标准样式的一栏 | 4×4 | 4×3 | 方便直接放一整块 |

**用量类**（属性：哪家 `source`，可选「合计」；统计范围 `range`：今天 / 本周期 / 7 天，默认跟窗口）

| 组件 | 来自现在的 | 默认 | 最小 | 额外属性 |
|---|---|---|---|---|
| 数值 | 大数字样式的一格 | 2×2 | 2×1 | 指标：成本 / 请求数 / Tokens / 命中率 |
| 走势图 | 走势图样式 | 4×2 | 3×2 | 起止时间标签开关 |
| 占比条 | 占比条样式 | 4×2 | 4×2 | — |
| 指标表 | 标准样式的一栏 | 4×3 | 3×3 | 选显示哪几项 |
| 周期历史 | 统计页「按周期」（**新组件，数据现成**） | 4×2 | 4×2 | 显示最近几个周期，第二批再做 |

**通用**

| 组件 | 默认 | 属性 |
|---|---|---|
| 标题（名字、套餐、「已用 / 剩余」） | 4×1 | 哪家、显示套餐 |
| 更新时间 | 4×1 | — |
| 文字 | 2×1 | 内容、字号、对齐 |

## 6. 编辑器（主窗口「卡片」页）

```
┌ 窗口 ─────┐┌──────── 画布（真实数据，显示网格） ────────┐┌ 属性 ───────┐
│ ● 额度     ││ [标题 Claude   ][标题 Codex    ]          ││ 圆环         │
│ ○ 用量     ││ [圆环 ][圆环  ] [圆环 ][圆环  ]           ││ 哪家  Claude │
│ + 新建     ││                                           ││ 额度  每周   │
│            │└───────────────────────────────────────────┘│ 覆盖样式 …   │
│ 模板 ▾     │ 组件栏：圆环 大数字 进度条 走势图 数值 …       │ 删除         │
└────────────┘                                              └──────────────┘
```

- 左边：窗口列表，新建时先选模板或预设尺寸；能复制、删除、显示 / 隐藏。
- 中间：画布用真实数据画，带网格线。点选组件；**第 3 步**先做「点组件栏 → 放到第一个空位」；**第 4 步**再加拖进来、拖动、拖边角改大小。
- 右边：没选组件时是窗口属性，选中时是组件属性。
- 放置规则：组件不能重叠、不能超出网格；拖到被占的位置就不让放（红框提示），一样大的两个组件可以互换。不自动往上挤。
- 撤销 / 重做：每次改动存一份配置快照。

## 7. 迁移

- 第一次启动新版时，把现在两张卡片的设置（显示与否、样式、排列、大小、背景、文字颜色、透明度、置顶、显示哪家、统计范围……）转成两个窗口，套用对应的模板，位置沿用。
- 旧的设置先保留不删，跑稳一个版本后再清理。

## 8. 两端怎么实现

**Mac（SwiftUI）**
- 配置用 Codable 结构体；组件渲染是一个按 `type` 分支的视图，现有的 `ringBlock`、`bigBlock`、`trendBlock` 等拆出来复用。
- 网格排版用 SwiftUI 的 `Layout` 协议（macOS 13 起有），每个组件放进算好的格子区域，套一层 `CardFrame` 做放大填满。
- 每个窗口一个 `CardWindow`，摆放的键改成按窗口 id。
- 编辑器的拖动用 `DragGesture`，坐标换算成格子后吸附。

**Windows/Linux（Tauri + 网页）**
- 渲染用 CSS Grid（`grid-column / grid-row` 跨格），组件里沿用现在的 HTML 片段和 `fitCardContent`。
- 窗口按需创建，标签 `widget-<id>`；权限配置里的窗口名单改成通配 `widget-*`；最多 6 个窗口。
- Rust 端 `Settings` 加 `widgets` 字段（组件的 `props` 用 `serde_json::Value`，不在 Rust 里逐个定义），摆放、贴边、对齐线、拖右下角缩放这些逻辑不变。
- 编辑器用 pointer 事件自己写，规则和 Mac 端一模一样。

**保持两边一致**
- 准备一组共用的 JSON 样例（每个模板、每种组件各一份），两边都拿来渲染出截图拼成对照图：Mac 用现有的离屏截图程序，Windows/Linux 用浏览器预览页。每一步结束时对一遍。

## 9. 分阶段

| 阶段 | 做什么 | 做完的标准 |
|---|---|---|
| 0 | 本计划 + 编辑器和几种窗口的效果图 | 你确认组件清单、网格尺寸、编辑方式 |
| 1 | 配置格式、两端渲染器、模板、迁移；Mac 补 limit 的 kind | 升级后两张卡片和 1.11 看起来一样；对照图两端一致 |
| 2 | 多窗口：新建、复制、删除、显示 / 隐藏，按 id 记位置 | 能同时开 3 个以上窗口，重启后位置和内容都在 |
| 3 | 列表式编辑器：组件栏点选添加、属性面板、实时预览、窗口属性 | 不用拖拽也能搭出任意布局。**到这一步合回 main 发版** |
| 4 | 画布拖拽：拖入、移动、改大小、互换、撤销重做 | 拖拽在两端手感一致，不会产生重叠或越界 |
| 5 | 模板：存为模板、导出 / 导入 JSON（跨平台通用） | Mac 导出的布局在 Windows 上导入后一样 |

第 1 步改动最大（两端的卡片代码都要按组件重组），但做完用户看不出变化，风险可控。

## 10. 风险

- **两套代码要一致**：组件越多越难对齐。靠共用 JSON 样例和对照图兜底，每加一个组件两边一起加。
- **小格子里的文字**：组件缩得太小时字会很小。每个组件设最小格数，编辑器里不让拖得更小。
- **Windows 上的内存**：每个窗口一个 WebView，限制窗口数量；以后可以考虑把同一屏的几个窗口合到一个 WebView 里。
- **迁移出错**：保留旧设置一个版本，出问题能回退。
- **编辑器工作量**：第 3 步先不做拖拽，先让功能完整可用，第 4 步再打磨手感。

## 11. 还要你定的

1. 网格每格 40pt、间距 8pt 这个粒度行不行（太细编辑麻烦，太粗排不开）。
2. 窗口数量上限 6 个够不够。
3. 新组件「预计用完」「周期历史」放进第一批，还是以后再加。
4. 卡片设置页里现在的「样式 / 排列」快捷切换，要不要在新版里保留成「一键换模板」。
